# Runtime dependencies for U-StarkPay — the Starknet whitelabel.
#
# This is the Sonic deployment's requirements.txt with the EVM SDKs
# removed, and starknet-py added.
#
# WHY THE EVM SDKs ARE NOT HERE
#
# Starknet is not EVM. But dataagent.py was carried over from U-bot
# Pay and imported three EVM things at module level:
#
#     from web3 import Web3
#     from eth_account import Account
#     from eth_account.messages import encode_typed_data
#
# On this deployment Web3 is used EXACTLY ONCE, for
# to_checksum_address, and Account and encode_typed_data are imported
# and NEVER USED. So the module pulled in a whole EVM SDK to use one
# checksum helper.
#
# And that SDK cannot be installed beside starknet-py:
#
#     starknet-py 0.30.0  ->  eth-keyfile <1.0.0, >=0.8.1
#     eth-account 0.14.0  ->  eth-keyfile >=0.10
#
# Those are incompatible. There are two ways pip meets that, and they
# fail differently - which is why the original failure was so hard to
# read.
#
# Both in one command - pip detects the conflict and installs nothing:
#
#     ERROR: Cannot install eth-account==0.14.0, starknet-py and
#     starknet-py==0.30.0 because these package versions have conflicting
#     dependencies.
#     ERROR: ResolutionImpossible
#
#     the exit code: 1
#
# In two steps - the EVM packages first, then starknet-py. pip resolves
# the conflict by DOWNGRADING eth-keyfile to 0.9.1, installs
# everything, and exits 0. The breakage is silent at install time and
# only shows up afterwards:
#
#     eth-account 0.14.0 requires eth-keyfile>=0.10, but you have
#     eth-keyfile 0.9.1 which is incompatible.
#
#     the exit code: 0
#
# That is why `pip check` is what the deployment script runs, and why
# it is FATAL (`|| exit 1`). The exit code of pip is not the signal:
# pip exits 0 on the path that leaves the environment broken.
#
# Two chain SDKs cannot share an interpreter. That is the same rule the
# engine registry follows, and the same thing that broke U-bot Pay's
# payments once before.
#
# There is no version combination that makes them coexist. Pinning
# eth-account below 0.14 does not help - the conflict moves to
# web3 itself:
#
#     pip install web3==8.0.0 'eth-account>=0.13,<0.14' starknet-py==0.30.0
#
#     ERROR: Cannot install eth-account<0.14 and >=0.13 and web3==8.0.0
#     because these package versions have conflicting dependencies.
#     ERROR: ResolutionImpossible
#
#     the exit code: 1
#
# So the separation is structural, not a version to be found.
#
# The EVM helpers come from evm_stub.py instead, which is what
# api.py already did. See that file for why skipping the EIP-55
# checksum is correct here rather than a shortcut.
#
