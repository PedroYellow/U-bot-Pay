## 🔴 CRÍTICO — `/turn` devuelve 500 en todas las peticiones (producto roto)

```
POST /turn {"user_key":"demo","text":"balance"}  -> 500 Internal Server Error
POST /turn {"text":"balance"}                    -> 500
POST /turn {"text":""}                           -> 500   (incluso texto vacío)
```

**Causa raíz: el LLM configurado no existe.**
`UBOT_LLM_URL=https://llm.u-topia.com/v1/chat/completions` (`.env.example:12`).
Verificado desde fuera:

```
getent hosts llm.u-topia.com  ->  NO RESOLVE
getent hosts u-topia.com      ->  185.158.133.1   (el dominio padre sí existe)
curl https://llm.u-topia.com/v1/models -> 000 (0.015s, sin conexión)
```

El subdominio `llm.` no resuelve. En `brain.py:67-73` la cadena es:

```python
if UBOT_LLM_URL:
    try:    raw = await _ubot(SYSTEM, text + ctx)
    except Exception:
        raw = None                      # <- silencioso
if raw is None:
    raw = await _fallback(SYSTEM, text + ctx)   # Anthropic, sin try/except
```

El fallback a Anthropic (`_fallback`, brain.py:52) **no está protegido** y sin
`ANTHROPIC_API_KEY` válido lanza excepción → 500. Además la primera rama se traga el
error real (`except Exception: raw = None`), así que el fallo de DNS es invisible en
la respuesta: solo aparece en los logs del servidor, y sin acceso SSH no se puede leer
el traceback exacto.

**Impacto**: el widget de voz de ElevenLabs, el bot de Telegram y la consola web
responden todos error. Un "`how much do I have?`" en demo = 500.

**Fix** (elegir uno):
1. Poner un LLM que exista y funcione (si hay uno nuevo, actualizar `UBOT_LLM_URL`).
2. Dejar `UBOT_LLM_URL` vacío y validar `ANTHROPIC_API_KEY` en el VPS.
3. Blindar `_fallback` con try/except y devolver un `intent` local por regex para
   que balance/send/etc. funcionen **sin** depender de ningún LLM. Esto es lo
   robusto: hoy el producto entero cae si una dependencia DNS externa falla.

Añadir healthcheck: `GET /health` sigue dando `{"ok":true}` con el cerebro caído, así
que cualquier monitor externo lo marca como **sano mientras está roto**.

## 🟠 ALTO — `/dashboard` público expone la tesorería

```
GET https://api.ubotpay.com/dashboard  (sin auth)  ->
{"ok":true,"chain":"avalanche-mainnet","chain_id":43114,"status":"live",
 "treasury_usdc":19.32,"treasury_avax":0.2933,"last_settlement_ts":0,
 "revenue_total_usdc":0,"ts":1792488155}
```

El docstring (api.py:321) dice "no auth" y justifica que son KPIs agregados, pero
`treasury_usdc` y `treasury_avax` **son el saldo exacto de la wallet que firma
transacciones**. No es un KPI agregado, es un inventario de un activo. Contradice el
audit #5, cuyo objetivo explícito era que la info de tesorería fuera solo por headers.

**Salidas**: 19.32 USDC + 0.2933 AVAX. El saldo bajó de 43.68 (15 Oct) → 19.32.

**Fix**: quitar `treasury_*` del payload público y dejarlos solo en `/health/full`
(auth), o redondearlos a bandas ("< 20 USDC") si la web los necesita para tiles.

## 🟡 MEDIO

### 1. `http://ubotpay.com` no redirige a HTTPS
```
curl -o /dev/null -w "%{http_code}" http://ubotpay.com  ->  200   (debería ser 301)
```
El audit del 15 Oct marcaba "HTTP→301 ✅". **Regresión.** El sitio se sirve en claro por
HTTP. Solo comprobé la home; falta verificar si aplica a `/api`, `/agent`, `/pitch`.

### 2. Cabeceras de seguridad ausentes en el sitio (sí están en la API)
```
ubotpay.com  ->  sin CSP, sin HSTS, sin X-Frame-Options, sin nosniff
api.ubotpay.com ->  CSP + HSTS + nosniff + X-Frame-Options: DENY  ✅
```
El sitio carga recursos de terceros (`cdn.jsdelivr.net`, `fonts.googleapis.com`,
`fonts.gstatic.com`, el widget de ElevenLabs). Sin CSP no hay control de qué scripts
pueden correr en una página que gestiona un wallet. **Este es el punto más sensible
que queda abierto**: el front toca la tesorería.

### 3. `/bridge/history` 500 sin token
```
GET /bridge/history (sin Authorization)  ->  500
GET /bridge/analytics (sin auth)          ->  401  {"auth required"}
```
Código correcto (api.py:997-1003 llama `_user_from_request` y hace `raise
HTTPException(401, err)`), así que el 500 viene de **dentro** de `_user_from_request`
o de `core.list_bridges`. Bug de la misma familia que `/turn`: excepción no
controlada donde debería haber un 401. **Sin traza no se confirma la línea exacta.**
